# Cangqiong CAPTCHA

**苍穹验证码 · Open-source CAPTCHA implemented in PHP/GD**

[简体中文](README.md) · [English](README.en.md)

An independently maintained PHP/GD CAPTCHA core with slider puzzles, ordered word clicks, rotation, image concatenation and a standalone POW core. Image generation and verification run entirely in PHP, without a hosted image service or external CAPTCHA platform. HTTP, frontend, storage, sessions and authentication belong to the host application.

## Requirements

- PHP 8.4 or newer; GD with JPEG, PNG and FreeType support; mbstring.
- A backend integration providing trusted server-side challenge storage, expiry, rate limits, session/purpose binding and atomic single-use consumption.
- A compatible browser SDK. The SDK is **not bundled**; the reference baseline and separate third-party frontend license are recorded in [UPSTREAM.md](UPSTREAM.md).

## Installation

The Composer package name is `xupaoye/cangqiong-captcha`. No stable tag has been released under this name, and it is not registered on Packagist. The following setup uses the main development branch. Production integrations should wait for a reviewed stable tag.

Add its VCS repository in the consuming application's root `composer.json`:

```json
{
  "repositories": [
    { "type": "vcs", "url": "https://github.com/XuPaoYe/cangqiong-captcha" }
  ],
  "require": {
    "xupaoye/cangqiong-captcha": "dev-main"
  }
}
```

Then run `composer update xupaoye/cangqiong-captcha`, review and commit your lock file. Once a stable release is available, use its reviewed tag constraint and deploy with `composer install`; do not automatically follow main in production. No GitHub token is required for ordinary public downloads, subject to GitHub rate limits. This repository has a new commit history and no published tags. Downloads of the previous repository’s historical versions are no longer guaranteed. Existing integrations require an explicit dependency and lock-file migration, not just a repository URL change. The `Foundation\Captcha` PHP namespace and public APIs remain unchanged.

## Image challenges

```php
use Foundation\Captcha\ImageCaptcha;

$engine = new ImageCaptcha();
$challenge = $engine->generate('SLIDER');

// Send ONLY this value to the browser:
$public = $challenge['public'];

// Store this value ONLY in trusted server-side storage:
$answer = $challenge['answer'];

// Later, retrieve the answer using a server-validated challenge ID and binding.
$passed = $engine->verify($answer, $submittedTrack);
```

Supported types: `SLIDER`, `WORD_IMAGE_CLICK`, `ROTATE`, `CONCAT`.

The library does not generate or persist image challenge IDs, handle HTTP, authenticate users, or issue reusable login tokens. The host application must assign unpredictable IDs, store answers privately, bind them to the current session and operation, expire them, and consume attempts atomically **including failed attempts**. A boolean sent back by the browser is never proof of verification. Do not let the browser submit its own answer or select a weaker verification policy.

Generated image size is 600×360; the supported browser display/track coordinates are 300×180. Rotation uses the compatible SDK's **242px** horizontal slider travel. Do not arbitrarily rescale submitted coordinates. A normal track contains `bgImageWidth`, `bgImageHeight`, integer millisecond `startTime` / `stopTime`, and `trackList` entries with `x`, `y`, `t`, `type`. Drag tracks start with `down` and end with `up`; ordered word targets use `click`. Coordinates/timestamps within track entries must be finite JSON numbers (numeric strings are rejected). Drag tracks contain only `down`, zero or more `move`, then `up`; click tracks permit `click` and pointer `move` events. Track duration must be 100–120000ms. These checks are input bounds, not a behavioral risk engine.

Slider challenges show one real target by default. Optional upstream-style decoys can be enabled with `new ImageCaptcha(sliderDecoy: true)`, but can make human matching ambiguous and are not recommended for normal login flows. Word hints are raster images with bounded randomized interference; target characters and answer coordinates are not exposed as JSON fields. This does not establish resistance to OCR or automated image matching.

### Custom resources

`new ImageCaptcha('/trusted/absolute/resource-directory')` selects another resource root containing `templates/`, `fonts/` and `backgrounds/`. JPEG backgrounds must be 720×432; dimensions/type are checked before bitmap decoding. The engine randomly samples `.jpg` files directly inside `backgrounds/`, then applies bounded crop, flip and brightness variation. Resource paths are trusted application configuration, never request parameters. Keep this directory private and controlled by the application owner; it is not an upload endpoint.

Five AI-generated landscape backgrounds are included. No customer data, framework code or project-specific portrait collection is distributed. See [resource provenance](resources/backgrounds/README.md) and [upstream differences](UPSTREAM.md).

Backgrounds can also be overridden without copying the bundled font/templates:

```php
$engine = new ImageCaptcha(
    backgroundDirectory: '/trusted/project/captcha-backgrounds',
    minimumCropUnits: ['portrait' => 138],
);
```

The crop map uses JPEG basenames without `.jpg`. Each minimum is an integer from 120 to 144; the sampled crop is `unit × 5` by `unit × 3` pixels. The default minimum120 allows600–720px widths;138 preserves more of a portrait with690–720px widths;144 disables spatial cropping. These are trusted resource preferences, not browser options. Missing/empty overrides fail closed instead of silently falling back.

## POW core

```php
use Foundation\Captcha\PowCaptcha;

$pow = new PowCaptcha();
$challenge = $pow->generate(); // default: [difficulty=4, saltLength=16, count=4]
$passed = $pow->verify($challenge['answer'], ['data' => $nonceString]);
```

The upstream browser protocol uses decimal nonces joined by `-` in `track.data`. This library verifies solutions; it never performs expensive solving on the server. Difficulty counts **hexadecimal digits**, not individual bits. Limits: difficulty 1–6, salt length 1–64, solution count 1–16; nonces must be canonical unsigned JavaScript-safe integers. Quoted, signed, fractional or exponent-form values are rejected.

POW proves computation cost, **not human presence**. It is not interchangeable with an interactive image challenge. Use a server-controlled policy and add the same session binding, expiry and single-use guarantees. This package does not provide an HTTP POW endpoint or claim production validation of the upstream browser worker lifecycle.

## Development and verification

```sh
composer install
composer validate --strict
composer resources:check
composer test
composer audit
```

Run the frozen baseline regression separately (also included in `composer test`):

```sh
composer parity
```

Development and tests require only PHP, its required extensions and Composer: no Java/JDK, Node.js or reference-source downloads. PHP tests compare 2,204 frozen decision inputs/expectations and 24,200 decoded cut-image pixels, with SHA256 integrity checks. See the [fixture provenance and maintenance rules](tests/fixtures/reference/README.md). This preserves the tested historical baseline, not a live comparison against Java or future upstream versions. New behavior belongs in independent project tests. CI covers PHP 8.4 and 8.5; application HTTP, database, browser, concurrency and deployment acceptance remain separate.

## Maintenance and security scope

This PHP library is maintained independently. Upstream is a reviewed reference, not an automatic update feed. Protocol compatibility is retained where useful; PHP input boundaries and usable defaults can deliberately be stricter. See [SECURITY.md](SECURITY.md) for the threat model and integration checklist. Passing parity/unit tests proves the tested decisions, not resistance to image solvers or a production false-accept rate.
